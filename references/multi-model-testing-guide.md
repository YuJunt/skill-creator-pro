# 多模型测试用例与评估方案

> skill-creator-pro 跨模型鲁棒性测试方案。验证技能在不同模型（GPT-4/Claude/Gemini/豆包等）下的触发率、路由输出率、流程完整性和输出质量是否一致。
> 核心结论：**技能的提示词和工作流设计应该对模型鲁棒，不依赖特定模型的特性。多模型测试是发现模型依赖问题的有效手段。**

---

## 一、测试目标

| 目标 | 说明 | 通过标准 |
|------|------|---------|
| **触发率一致性** | 不同模型下，相同用户输入是否都能触发技能 | 触发率差异 < 10% |
| **路由输出率** | 技能触发后，不同模型是否都能输出路由行 | 路由输出率 > 90%（所有模型） |
| **流程完整性** | 不同模型是否都能完整执行工作流，不跳步 | 流程完成率 > 85% |
| **输出质量** | 不同模型的输出质量是否一致 | 质量评分差异 < 15% |
| **错误恢复** | 遇到错误时，不同模型是否都能正确处理 | 错误恢复率 > 80% |

---

## 二、测试维度

### 维度1：触发率测试

**测试方法**：准备20条不同风格的用户输入，在每个模型下运行，统计技能被触发的比例。

**测试用例**：

| 编号 | 用户输入 | 预期触发 | 输入风格 |
|------|---------|---------|---------|
| T1 | "帮我创建一个技能" | ✅ | 直接明确 |
| T2 | "这个技能有什么问题" | ✅ | 口语化 |
| T3 | "优化一下我的skill" | ✅ | 中英混合 |
| T4 | "帮我看看这个技能还能怎么改进" | ✅ | 长句口语 |
| T5 | "技能审计" | ✅ | 极简关键词 |
| T6 | "review my skill" | ✅ | 英文 |
| T7 | "测试一下这个技能的质量" | ✅ | 间接表达 |
| T8 | "我想做一个自定义技能" | ✅ | 意图表达 |
| T9 | "今天天气怎么样" | ❌ | 无关对话（不应触发） |
| T10 | "帮我写个prompt" | ❌ | 相关但不匹配（不应触发） |

**通过标准**：
- 应触发的用例（T1-T8）触发率 > 90%
- 不应触发的用例（T9-T10）误触发率 < 10%
- 各模型间触发率差异 < 10%

---

### 维度2：路由输出率测试

**测试方法**：技能触发后，统计模型输出中包含路由行（`🔀 路由: {模式}`）的比例。

**测试用例**：

| 编号 | 场景 | 预期路由 |
|------|------|---------|
| R1 | 用户说"帮我创建一个技能" | 🔀 路由: 新建技能 |
| R2 | 用户说"优化一下这个技能" | 🔀 路由: 优化技能 |
| R3 | 用户说"评审一下这个技能" | 🔀 路由: 深度评审 |
| R4 | 用户说"测试一下这个技能" | 🔀 路由: 端到端测试 |
| R5 | 用户说"继续"（上一轮已触发技能） | 应保持路由（会话保持） |
| R6 | 用户说"好的"（上一轮已触发技能） | 应保持路由（会话保持） |

**通过标准**：
- 路由行输出率 > 90%（所有模型）
- 路由模式选择正确率 > 85%
- 长对话（R5/R6）路由保持率 > 70%
- 各模型间路由输出率差异 < 10%

---

### 维度3：流程完整性测试

**测试方法**：统计模型是否完整执行工作流的所有步骤，不跳步、不偷懒。

**optimize模式完整流程（4步）**：
1. ✅ 规范校验（validate_skill.py）
2. ✅ 深度审计（audit_skill.py）
3. ✅ 安全扫描（security_scan.py）
4. ✅ 输出校验（output_validator.py）

**测试用例**：

| 编号 | 场景 | 预期步骤数 |
|------|------|-----------|
| F1 | 完整优化流程 | 4步全部执行 |
| F2 | 完整评审流程 | 3步全部执行 |
| F3 | 完整测试流程 | 包含脚本冒烟测试 |
| F4 | 用户催促"快点" | 仍应执行所有步骤（不跳步） |
| F5 | 用户说"简单点" | 仍应执行核心步骤（不少于3步） |

**通过标准**：
- 流程完成率 > 85%（所有模型）
- 核心步骤（规范校验+输出校验）执行率 100%
- 各模型间流程完成率差异 < 15%

---

### 维度4：输出质量测试

**测试方法**：对模型的输出进行质量评分（1-10分），评估内容完整性、准确性、专业性。

**评分维度**：

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| **内容完整性** | 30% | 是否包含所有必需字段（结论/方案/理由/风险提示） |
| **准确性** | 25% | 分析结论是否正确，是否有事实错误 |
| **专业性** | 20% | 是否引用了方法论/最佳实践，术语使用是否准确 |
| **格式规范性** | 15% | 输出格式是否符合模板要求，路由行是否正确 |
| **可操作性** | 10% | 建议是否具体可执行，不是空泛的"需要改进" |

**通过标准**：
- 平均质量评分 > 7分（所有模型）
- 各模型间质量评分差异 < 15%
- 无严重事实错误（0分项）

---

### 维度5：错误恢复测试

**测试方法**：构造异常场景，测试模型是否能正确识别错误并恢复。

**测试用例**：

| 编号 | 异常场景 | 预期行为 |
|------|---------|---------|
| E1 | 技能目录不存在 | 明确报错，不继续执行 |
| E2 | SKILL.md格式错误 | 规范校验发现问题，提示修复 |
| E3 | 安全扫描发现高风险 | 中止流程，提示必须修复 |
| E4 | 输出校验失败 | 提示具体问题，要求修复后重新运行 |
| E5 | 脚本运行超时 | 提示超时，建议检查环境 |

**通过标准**：
- 错误识别率 > 90%（所有模型）
- 错误恢复率 > 80%（能给出正确的修复建议）
- 各模型间错误处理差异 < 15%

## 三、执行方法

### 3.1 测试环境准备

```bash
# 1. 准备测试用的技能目录
mkdir -p /tmp/test-skill
python3 scripts/init_skill_pro.py test-skill --path /tmp --philosophy mixed

# 2. 准备测试输入列表（见上文测试用例）
# 3. 在每个模型下运行相同的测试用例
# 4. 记录结果并对比
```

### 3.2 结果记录模板

```markdown
## 多模型测试结果对比

| 测试维度 | GPT-4 | Claude 3 | Gemini | 豆包 | 差异 |
|---------|-------|----------|--------|------|------|
| 触发率 | 95% | 90% | 85% | 92% | 10% |
| 路由输出率 | 95% | 85% | 80% | 90% | 15% |
| 流程完成率 | 90% | 80% | 75% | 85% | 15% |
| 输出质量 | 8.5 | 7.5 | 7.0 | 8.0 | 1.5 |
| 错误恢复率 | 90% | 80% | 75% | 85% | 15% |

## 发现的模型依赖问题

1. [问题描述] - 影响模型：[模型列表] - 严重度：[高/中/低]
2. ...

## 改进建议

1. [具体改进建议]
2. ...
```

### 3.3 问题分类与处理

| 问题类型 | 处理方式 |
|---------|---------|
| **某模型触发率低** | 优化description，增加该模型擅长识别的触发词 |
| **某模型路由输出率低** | 强化路由行指令，增加示例，降低格式复杂度 |
| **某模型跳步** | 增加硬门禁（脚本校验），强化"不允许跳过"指令 |
| **某模型输出质量低** | 增加输出模板和示例，明确质量标准 |
| **某模型错误处理差** | 增加错误处理指南，强化"遇到错误必须报错"指令 |

## 四、当前技能的多模型鲁棒性设计

skill-creator-pro 已经采用了以下多模型鲁棒性设计：

| 设计 | 作用 | 覆盖维度 |
|------|------|---------|
| **P0扩大触发范围** | 20+口语化触发场景，不依赖精确匹配 | 触发率 |
| **P1简化路由格式** | 1字段极简格式，降低模型输出成本 | 路由输出率 |
| **P2会话保持** | 明确要求每轮输出路由行，防止长对话丢失 | 长对话保持 |
| **P3编排脚本硬校验** | 脚本自动输出路由行，模型想忘都忘不了 | 路由输出率 |
| **4步硬门禁校验** | 规范/审计/安全/输出，脚本校验不通过就中止 | 流程完整性 |
| **command参数required=True** | 不传模式脚本直接报错，强制模型先确定模式 | 流程完整性 |
| **错误处理友好** | 所有脚本对异常输入明确报错返回码1 | 错误恢复 |

## 五、检查清单：你的多模型测试是否完整

- [ ] 是否覆盖5个测试维度（触发/路由/流程/质量/错误）？
- [ ] 是否准备了至少20条测试用例？
- [ ] 是否在至少3个不同模型下运行？
- [ ] 是否记录了量化结果（百分比/评分）？
- [ ] 是否对比了模型间差异？
- [ ] 是否发现了模型依赖问题？
- [ ] 是否给出了改进建议？
- [ ] 是否验证了改进效果？

**0-3项**：多模型测试严重不足，技能可能存在模型依赖问题
**4-6项**：多模型测试基本完整，但有遗漏维度
**7-8项**：多模型测试完整，技能对模型鲁棒
