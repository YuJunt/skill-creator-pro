# 自由度匹配（Degrees of Freedom）

> 基于Anthropic官方最佳实践 + effective-agent-skills业界指南整理
> 核心思想：指令的严格程度要与任务的脆弱性匹配。太松会出错，太严会浪费agent的能力。

---

## 一、什么是自由度

**定义**：自由度是指agent在执行任务时有多少选择空间——是必须严格按指令做，还是可以根据情况灵活调整。

**为什么重要**：
- 任务脆弱（出错代价高）→ 需要低自由度（严格指令）
- 任务灵活（多种方法都可以）→ 需要高自由度（宽松指令）
- 不匹配的后果：
  - 脆弱任务给高自由度 → agent自由发挥，容易出错
  - 灵活任务给低自由度 → agent被束缚，浪费能力，输出僵硬

---

## 二、三档自由度

### 高自由度（High Freedom）—— 文本指令为主

**特征**：
- 用自然语言描述目标和原则，不指定具体步骤
- agent可以选择多种方法实现目标
- 决策依赖上下文和agent的判断
- SKILL.md典型内容：目标描述+原则+示例+注意事项

**适用场景**：
- 多种方法都有效，没有唯一正确答案
- 决策依赖上下文（不同情况用不同方法）
- 需要创造力/判断力/灵活性
- 出错代价低（错了可以改）

**典型例子**：
- 内容创作（写文章/写代码/设计方案）
- 研究综合（收集信息+分析+总结）
- 问题诊断（分析问题原因+提出解决方案）
- 对话交互（客服/咨询/讨论）

**SKILL.md写法示例**：
```markdown
## 目标
帮助用户创建有效的技能。

## 原则
1. 先理解用户需求，再设计方案
2. 技能要简洁，不堆砌功能
3. 每个功能都要有评估用例

## 示例
用户说"创建一个PDF处理技能"
→ 先问清楚需求（需要哪些功能？）
→ 设计方案（包装哪些库？）
→ 实现（写SKILL.md+脚本）
→ 测试（跑评估用例）

## 注意事项
- 不要创建用户没要求的功能
- 不要把简单问题复杂化
```

---

### 中自由度（Medium Freedom）—— 伪代码/参数化脚本

**特征**：
- 有推荐的流程/模式，但允许一些变化
- 配置/参数影响行为，但核心流程固定
- agent在固定框架内做判断
- SKILL.md典型内容：流程步骤+参数说明+示例+变体

**适用场景**：
- 有首选模式，但有些变化可以接受
- 配置影响行为（不同参数不同结果）
- 核心流程固定，细节可以灵活
- 出错代价中等（流程对了质量就有保障）

**典型例子**：
- 数据分析（固定流程：采集→清洗→分析→可视化，参数灵活）
- 代码审查（固定checklist，判断灵活）
- 文档生成（固定模板，内容灵活）
- 测试执行（固定测试流程，用例灵活）

**SKILL.md写法示例**：
```markdown
## 流程
1. 数据采集（参数：数据源/时间范围）
2. 数据清洗（参数：清洗规则/缺失值处理）
3. 数据分析（参数：分析方法/指标）
4. 可视化（参数：图表类型/样式）

## 参数说明
- 数据源：支持CSV/API/数据库
- 分析方法：支持描述性/推断性/预测性
- 图表类型：支持折线/柱状/饼图/散点

## 示例
用户说"分析最近30天的销售数据"
→ 数据源：销售API
→ 时间范围：最近30天
→ 分析方法：描述性（趋势+对比）
→ 图表类型：折线图（趋势）+柱状图（对比）

## 变体
- 如果数据量小，可以跳过清洗步骤
- 如果用户指定了分析方法，用用户指定的
```

### 低自由度（Low Freedom）—— 具体脚本/固定参数

**特征**：
- 操作是固定的，必须严格按步骤执行
- 脚本/命令是固定的，参数很少
- agent的工作是选择正确的命令+执行+解释结果
- SKILL.md典型内容：命令列表+参数说明+输出解释+错误处理

**适用场景**：
- 操作脆弱且容易出错（必须精确执行）
- 一致性至关重要（每次都要一样的结果）
- 必须遵循特定顺序（步骤不能乱）
- 出错代价高（错了可能造成损失）

**典型例子**：
- 文件操作（删除/移动/重命名——必须精确）
- 数据库操作（查询/更新——必须精确）
- API调用（参数必须正确）
- 部署操作（顺序不能乱）

**SKILL.md写法示例**：
```markdown
## 命令列表

### 1. 提取PDF文本
命令：python3 scripts/extract_text.py <input.pdf> <output.txt>
参数：
- input.pdf：输入PDF文件路径（必填）
- output.txt：输出文本文件路径（必填）
输出：提取的文本内容
错误处理：
- 文件不存在 → 报错"输入文件不存在"
- 密码保护 → 报错"PDF需要密码"

### 2. 合并PDF
命令：python3 scripts/merge_pdf.py <input1.pdf> <input2.pdf> ... <output.pdf>
参数：
- input1.pdf, input2.pdf, ...：输入PDF文件（至少2个）
- output.pdf：输出PDF文件（必填）
输出：合并后的PDF
错误处理：
- 文件数<2 → 报错"至少需要2个输入文件"
- 文件格式错误 → 报错"文件不是有效的PDF"

## 使用流程
1. 确认用户需求（提取/合并/旋转/...）
2. 选择对应的命令
3. 确认参数（文件路径/选项）
4. 执行命令
5. 解释输出结果
6. 处理错误（如有）
```

## 三、如何选择自由度

### 决策树

```
任务的脆弱性如何？
│
├─ 高（出错代价高，必须精确执行）
│   └─ → 低自由度（具体脚本/固定参数）
│
├─ 中（流程对了质量就有保障）
│   └─ → 中自由度（伪代码/参数化脚本）
│
└─ 低（多种方法都可以，错了可以改）
    └─ → 高自由度（文本指令为主）
```

### 选择检查清单

**选低自由度，如果**：
- [ ] 操作脆弱且容易出错
- [ ] 一致性至关重要（每次都要一样的结果）
- [ ] 必须遵循特定顺序（步骤不能乱）
- [ ] 出错代价高（错了可能造成损失）
- [ ] 已有现成的脚本/命令可以直接用

**选中自由度，如果**：
- [ ] 有首选模式，但有些变化可以接受
- [ ] 配置/参数影响行为
- [ ] 核心流程固定，细节可以灵活
- [ ] 出错代价中等（流程对了质量就有保障）
- [ ] 需要agent在固定框架内做判断

**选高自由度，如果**：
- [ ] 多种方法都有效，没有唯一正确答案
- [ ] 决策依赖上下文（不同情况用不同方法）
- [ ] 需要创造力/判断力/灵活性
- [ ] 出错代价低（错了可以改）
- [ ] 没有现成的脚本/命令，需要agent自己想方法

## 四、混合自由度（复杂技能的常态）

**现实中，复杂的技能往往是混合自由度**：
- 脆弱的部分用低自由度（脚本化）
- 灵活的部分用高自由度（文本指令）
- 中间的部分用中自由度（参数化流程）

**混合自由度的设计原则**：
1. 按步骤/模块划分自由度，不是整个技能一个自由度
2. 脆弱的步骤必须低自由度（脚本化+硬校验）
3. 灵活的步骤可以高自由度（文本指令+示例）
4. SKILL.md里明确标注每个步骤的自由度
5. agent知道哪些步骤必须严格执行，哪些可以灵活调整

**示例**：
```markdown
## 流程

### Step 1: 数据采集（低自由度）
命令：python3 scripts/fetch_data.py --source <source> --count <count>
必须严格执行，参数必须正确。

### Step 2: 数据分析（中自由度）
流程：计算指标→识别模式→评估信号
参数：分析期数/指标选择可灵活
核心流程固定，细节可调整。

### Step 3: 决策推荐（高自由度）
目标：根据分析结果，给出最优推荐
方法：可以用决策树/经验/直觉，灵活选择
输出格式固定，内容灵活。

### Step 4: 校验写库（低自由度）
命令：python3 create_skill.py continue --result-json '<json>'
必须严格执行，缺字段就报错。
```

## 五、常见错误

### 错误1：所有步骤都用高自由度
**症状**：连数据采集/校验写库这种脆弱步骤都让agent自由发挥，经常出错
**修正**：脆弱步骤必须低自由度（脚本化+硬校验）

### 错误2：所有步骤都用低自由度
**症状**：连决策推荐这种需要判断的步骤都写成固定脚本，输出僵硬，没有发挥agent的能力
**修正**：灵活步骤可以高自由度（文本指令+示例）

### 错误3：脆弱步骤给高自由度
**症状**：文件删除/数据库更新这种操作让agent自由写命令，容易误删/误更新
**修正**：必须低自由度，用固定脚本+参数校验+确认机制

### 错误4：灵活步骤给低自由度
**症状**：内容创作/问题诊断这种需要创造力的任务写成固定流程，输出千篇一律
**修正**：可以高自由度，给目标+原则+示例，让agent自由发挥

### 错误5：不标注自由度，agent不知道哪些可以灵活
**症状**：SKILL.md里没有标注自由度，agent对所有步骤都用同样的严格程度
**修正**：明确标注每个步骤的自由度，agent知道哪些必须严格执行，哪些可以灵活调整

## 六、检查清单：你的技能自由度是否匹配

- [ ] 每个步骤/模块都有明确的自由度标注（高/中/低）
- [ ] 脆弱步骤（数据采集/校验/写库/文件操作）用低自由度
- [ ] 灵活步骤（决策/创作/诊断）用高自由度
- [ ] 中间步骤（分析/处理）用中自由度
- [ ] 低自由度步骤有固定脚本/命令+参数说明+错误处理
- [ ] 中自由度步骤有推荐流程+参数说明+变体
- [ ] 高自由度步骤有目标+原则+示例+注意事项
- [ ] agent知道哪些步骤必须严格执行，哪些可以灵活调整
- [ ] 没有脆弱步骤给高自由度的情况
- [ ] 没有灵活步骤给低自由度的情况

**0-4项**：自由度不匹配，需要重新梳理
**5-7项**：自由度基本匹配，有优化空间
**8-10项**：自由度匹配合理，技能结构清晰
