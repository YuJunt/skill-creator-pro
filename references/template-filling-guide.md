# 模板填充指南

> 基于skill-creator-pro的14个模板字符串总结。每个模板中的占位符都有明确的填充要求，按照本指南填充可以确保生成的技能符合专业标准。
> 核心结论：**模板不是"填完TODO就行"，而是每个占位符都有质量标准。按照本指南逐项填充，生成的技能可以直接达到80分以上。**

---

## 一、SKILL.md 模板填充指南（最重要）

SKILL.md是技能的入口，也是质量的关键。有3种模板：MIXED（混合模式）、CAPABILITY（能力模式）、PROCESS（流程模式）。

### 1.1 frontmatter（YAML头部）

| 占位符 | 填充要求 | 示例 | 质量标准 |
|--------|---------|------|---------|
| `name` | 技能名称，小写+连字符 | `pdf-editor` | 与目录名一致，不含空格/大写 |
| `description` | 三要素：What+When+Differentiator | "PDF文档编辑工具，支持旋转/合并/拆分/提取文字。当用户需要处理PDF文件时使用。" | 包含触发词，50-200字，不写"今天""最新" |

**description三要素详解：**
- **What**：技能做什么（1-2句话）
- **When**：什么时候触发（具体场景/文件类型/任务）
- **Differentiator**：与其他技能的区别（可选，但有更好）

### 1.2 标题和概述

| 占位符 | 填充要求 | 示例 |
|--------|---------|------|
| `{skill_title}` | 技能的中文标题 | `PDF编辑工具` |
| 概述段落 | 1-2句话说明技能能做什么 | "本技能提供PDF文档的完整编辑能力..." |

### 1.3 触发路由（多模式技能必填）

如果技能支持多种模式（完整/快速/单步），必须在SKILL.md中添加模式路由表：

| 列 | 填充要求 |
|----|---------|
| 模式 | 模式名称（完整模式/快速模式/单步执行） |
| 触发词 | 用户说什么词时触发这个模式 |
| 管道 | 这个模式走哪些步骤 |
| 必读文档 | 这个模式需要读哪些references |
| 输出详略 | 输出是完整版还是极简版 |

### 1.4 工作流程步骤

每个步骤必须包含：
- **做什么**：具体说明这一步要做什么
- **检查清单**：2-5个检查项，用`[ ]`标记
- **必读**：需要读哪个references文档的哪一章
- **通过标准**：明确的完成标准（不是"完成即可"，而是"输出包含XX字段"）

### 1.5 Gotchas（常见陷阱）

必须包含至少3个具体的失败模式和修正方法：

| 格式 | 示例 |
|------|------|
| ❌ 错误做法 → ✅ 正确做法 | ❌ 直接用`os.system`调用外部命令 → ✅ 用`subprocess.run`并检查返回码 |

**Gotchas质量标准：**
- 必须是具体的失败模式，不是抽象规则
- 必须有修正方法
- 至少3个，最好5个以上
- 来自实际开发经验，不是凭空想象

### 1.6 渐进式披露（references引用）

每个references文档必须在SKILL.md中说明"什么时候读"：

| 格式 | 示例 |
|------|------|
| 做什么 → 读哪个文档 | 需要详细的工作流步骤 → 读 `references/workflow-guide.md` |

**渐进式披露质量标准：**
- 每个references文件都必须被引用
- 引用必须说明"什么时候读"，不是"有这个文件"
- 大文件（>100行）必须说明读哪一章

## 二、脚本模板填充指南

### 2.1 orchestrator.py（编排脚本）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题，用于日志输出 |
| `# TODO: 实现各阶段逻辑` | 实现每个阶段的具体逻辑（调用其他脚本/函数） |

**orchestrator质量标准：**
- 必须有状态管理（stage状态，防止重复执行）
- 必须有错误处理（每个阶段失败时记录错误并继续）
- 必须有日志输出（每个阶段开始/结束时输出）
- 必须有CLI入口（`if __name__ == "__main__"`）

### 2.2 validator.py（校验脚本）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题 |
| `validate_file`函数 | 实现具体的校验逻辑（检查必填字段/格式/范围） |

**validator质量标准：**
- 必须有明确的校验规则（什么算通过，什么算失败）
- 必须有错误信息（失败时说明哪里错了，怎么改）
- 必须有返回值（成功返回True，失败返回False+错误列表）

### 2.3 main.py（能力模式主脚本）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题 |
| 核心函数 | 实现技能的核心功能 |

## 三、references模板填充指南

### 3.1 best-practices.md（最佳实践）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题 |
| 最佳实践内容 | 3-5条具体的最佳实践，每条有"为什么"和"怎么做" |

### 3.2 workflow-guide.md（工作流指南）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题 |
| 工作流步骤 | 每个步骤的详细说明（输入/处理/输出/常见错误） |

### 3.3 checklist.md（检查清单）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题 |
| 检查项 | 10-20个检查项，按类别分组，每项有通过标准 |

### 3.4 evaluation-cases.md（评估用例）

| 占位符 | 填充要求 |
|--------|---------|
| `{skill_title}` | 技能标题 |
| 评估用例 | 至少3个用例，每个有输入/预期输出/通过标准 |

## 五、填充顺序建议

按照以下顺序填充，可以最高效地完成技能创建：

1. **先填SKILL.md的frontmatter**（name/description）——确定技能的身份
2. **再填SKILL.md的概述和触发路由**——确定技能的能力范围
3. **然后填工作流程步骤**——确定技能的执行流程
4. **接着填Gotchas**——基于开发经验添加常见陷阱
5. **最后填references和examples**——补充详细文档和示例
6. **实现脚本**——根据工作流程实现orchestrator/validator等脚本

## 六、填充完成后的自检清单

填充完成后，用以下清单自检：

- [ ] SKILL.md的frontmatter有name和description吗？
- [ ] description包含触发词吗？
- [ ] SKILL.md有触发路由表吗（多模式技能）？
- [ ] 每个工作流步骤有检查清单和通过标准吗？
- [ ] 有至少3个Gotchas吗？
- [ ] 每个references文件都在SKILL.md中被引用了吗？
- [ ] 引用说明了"什么时候读"吗？
- [ ] 脚本有`if __name__ == "__main__"`入口吗（非模块文件）？
- [ ] 脚本有错误处理吗？
- [ ] examples有完整的示例吗？
- [ ] evaluation-cases有至少3个用例吗？

**0-4项**：填充不足，技能质量没有保障
**5-8项**：基本填充完成，有少量遗漏
**9-12项**：完整填充，技能质量有保障
