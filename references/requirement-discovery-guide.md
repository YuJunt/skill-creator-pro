# 需求发现：从不完备Brief到完整技能规格

> 基于arXiv:2608.23417 SkillAlchemy论文。核心结论：**用户的brief通常不完备——你需要主动发现遗漏的需求，而不是照做。**

---

## 一、问题：为什么用户brief不完备

```
用户说："帮我做一个PDF处理技能"
  → 他以为你知道：哪些操作？输出什么格式？错误怎么处理？
  → 实际他没说：需要OCR吗？密码保护PDF怎么办？批量处理吗？
```

**常见遗漏：**
1. 边界场景（空文件/超大文件/损坏文件）
2. 错误处理（文件不存在/权限不够/格式不对）
3. 输出格式（文本还是结构化JSON？）
4. 性能要求（单文件还是批量？多大？）
5. 依赖假设（用户有Python环境吗？需要安装什么？）

---

## 二、需求发现清单

在创建技能前，逐项确认：

### 2.1 功能范围
- [ ] 核心功能是什么？（用户说的）
- [ ] 边界场景有哪些？（空/超大/损坏/边界值）
- [ ] 不支持什么？（明确排除范围）

### 2.2 输入输出
- [ ] 输入格式是什么？（文件类型/大小/编码）
- [ ] 输出格式是什么？（文本/JSON/文件）
- [ ] 输出到哪里？（屏幕/文件/云端）

### 2.3 错误处理
- [ ] 输入错误怎么提示？
- [ ] 依赖不可用怎么降级？
- [ ] 用户怎么知道出错了？

### 2.4 用户体验
- [ ] 快速模式有吗？（用户说"简单说下"）
- [ ] 详细模式有吗？（用户说"完整分析"）
- [ ] 手机端输出还是电脑端？

### 2.5 工程要求
- [ ] 需要联网吗？
- [ ] 需要本地脚本吗？
- [ ] 需要持久化存储吗？

## 三、发现方法

### 3.1 追问策略

```
不要一次问完所有问题（用户会烦）：
  1. 先做最小可行版本（MVP）
  2. 跑起来发现问题
  3. 根据实际问题补充需求
  4. 迭代2-3轮后趋于稳定
```

### 3.2 模板填空法

```
用户说："做一个X技能"
你自动补全：
  - X的核心操作是什么？
  - 输入是什么？输出是什么？
  - 常见错误有哪些？
  - 成功的标准是什么？
然后向用户确认："我理解你需要的是A+B+C，对吗？"
```

---

## 四、检查清单

- [ ] 是否主动发现了用户没说的边界场景？
- [ ] 是否明确了输入输出格式？
- [ ] 是否考虑了错误处理和降级？
- [ ] 是否区分了快速模式和详细模式？
- [ ] 是否先做MVP再迭代？
- [ ] 是否向用户确认了你的理解？

**0-2项**：需求发现不足
**3-4项**：基本发现
**5-6项**：专业需求发现
