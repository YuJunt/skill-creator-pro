# 复杂技能设计指南（Complex Skill Guide）

> **🎯 什么时候读我**：创建或优化**复杂技能**（持续运行型/数据沉淀型/主动触达型）时，按本文档设计架构与可选层能力路径。
> **❌ 不需要读我**：简单技能（单步工具/方法论文档/一次性产出）——直接用模板即可，本文档的可选层全部记为「不适用（N/A）」。
> **核心定位**：skill-creator-pro 是**通用**技能创建器——既能创建/优化简单技能，也完整保留复杂技能的创建与优化路径。本指南就是复杂技能的能力地图。

---

## 一、什么是"复杂技能"（适用性判定）

复杂技能 ≠ "内容多"，而是**运行方式**与简单技能不同。用三个问题判定：

| 判定问题 | 是 → 复杂技能 | 否 → 简单技能 |
|---------|-------------|-------------|
| ① 有固定运行节奏吗？ | 每天/每周自动跑（结果发布后分析、收盘后复盘、每日报告） | 用户问才跑 |
| ② 产生跨期复用的数据吗？ | 历史记录/战绩/经验/状态需要沉淀到下期 | 输出即交付，无状态 |
| ③ 结果需要主动触达用户吗？ | 推送报告/预警/提醒 | 用户回来查看 |

**≥2 个"是"** → 复杂技能，按本指南设计；否则为简单技能。

**典型复杂技能**：彩票预测（每日结果发布+历史战绩+报告推送）、市场监控（持续跟踪+告警）、定时报表（每日生成+推送）、PR 自动监控（babysit 类）。
**典型简单技能**：文档格式转换、代码审查、方法论文档、单次数据整理。

## 二、复杂技能架构：职责边界模式

> 官方/业界职责共识：**Agent 管目标、Workflow 管流程、Skill 管方法、MCP 管连接、脚本管确定性、平台/基础设施管存储与调度**。
> 复杂技能 = 在 Skill 内组织好"脚本确定性计算 + AI 决策 + 平台能力 + 云端存储"四方的分工。

| 方 | 职责 | 禁止 |
|----|------|------|
| **脚本（scripts/）** | 确定性计算：数据采集/指标计算/数量计算/命中核对/状态管理 | ❌ 做分析推理/决策判断 |
| **AI（LLM）** | 决策：信号诊断/方案选择/复盘反思/报告撰写/流程编排 | ❌ 手算确定性结果 |
| **平台能力** | 调度：定时任务/搜索兜底/长期记忆/可视化 | ❌ 替代业务逻辑 |
| **云端（Base/Doc/IM）** | 持久化：历史数据/报告存档/经验库/通知推送 | ❌ 做分析决策 |

**实现要点**：
1. **orchestrator.py 是骨架**：start（采集+计算）→ continue（校验+落库）→ settle（结算+复盘），每阶段有状态门禁
2. **脚本只做确定性**：所有可计算/可断言的操作进脚本，LLM 只读输出做判断
3. **状态持久化**：state.json 防重复执行；关键数据落云端

## 三、可选层能力路径（复杂技能的 6 项增强，按需启用）

> 每项都有「最小实现 → 完整实现」两档。**先用最小实现跑通，验证确有需要再升级**——不要一开始就全量建设。

### 3.1 定时任务（有固定节奏时）
- **最小实现**：SKILL.md 写明运行节奏（如"每日 11:30 后执行"），由平台定时任务触发
- **完整实现**：配置平台 cron 任务（早盘/中盘/临场/结算多档），query 指向最新流程
- **⚠️ 已验证的坑**：文档声称配置了定时任务但实际为 0——**必须真实创建并验证可触发**，不能只写在文档里

### 3.2 云端持久化（需跨期数据时）
- **最小实现**：本地 runtime/ 目录 JSON 落盘（跨会话保留，重启不丢）
- **完整实现**：云端 Base（历史记录/战绩/经验库/账户状态），写入失败自动降级本地备份
- **⚠️ 已验证的坑**：脚本写了 云端写入脚本 但凭据未配置、写入走降级——**必须真实配置凭据并验证写入成功**

### 3.3 通知推送（需主动触达时）
- **最小实现**：对话内交付 + 明确"结果已生成，可随时查看"
- **完整实现**：IM webhook 推送交互卡片（摘要+报告链接）

### 3.4 指标监控（有效果指标时）
- **最小实现**：本地 stats.json 累计命中率/成功率
- **完整实现**：指标入库 + 数据驱动优化（对比各方案表现）

### 3.5 经验回流（需越用越准时）
- **最小实现（推荐先用这个）**：复盘后把经验追加进 SKILL.md 的 Gotchas 章节——这就是官方"**Gotchas 飞轮**"理念，成本最低、ROI 最高
- **完整实现**：独立经验库（经验 ID/标签/置信度/命中率）+ 查询接口，下批执行时读取

### 3.6 职责边界（架构组织方式）
- 不是独立能力，而是上面各项的组织模式。简单技能不需要；复杂技能用它保持职责清晰。

## 四、用 skill-creator-pro 创建复杂技能的步骤

```
1. init_skill_pro.py 生成骨架（任意 philosophy，推荐 mixed）
2. 按业务拆确定性脚本（数据采集/计算/校验），写 orchestrator.py 状态机
3. SKILL.md 补：决策树+候选输出 / 自进化闭环 / 安全考虑（模板已自带 ✅）
4. 按需启用可选层（先最小实现，验证后再升级）：
   - 定时任务 → 真实创建平台 cron 并验证触发
   - 云端持久化 → 配置凭据，验证写入成功
   - 通知推送 → webhook 验证送达
   - 经验回流 → 先 Gotchas 追加，需要时再建经验库
5. 跑全套校验：validate → audit（推荐层 10/10，可选层按适用性判定）→ output_validator → 端到端实测 → gate
```

**创建简单技能**：同一入口，跳过第 3-4 步（可选层全部 N/A），推荐层由模板保证 10/10。

## 五、优化既有技能的路径

```
1. review 模式审计：必备层硬门禁 → 推荐层缺口 → 可选层适用性判定
2. 按优先级修复（P0 阻塞 → P1 严重 → P2 中等 → P3 低）
3. 复杂技能重点查：orchestrator 状态机 / 定时任务真实性 / 云端写入真实性 / 经验闭环是否真的在跑
4. 修复后：validate + audit + output_validator + 端到端实测 + gate 全绿才交付
```

**⚠️ 注意**：audit 评分工具存在已知误判倾向（Gotchas 识别、时间敏感词、单一职责），**复杂技能的评审必须配人工交叉核查**，不能只信工具分数。

## 六、复杂技能质量底线（交付前自查）

- [ ] 必备层 20/20（硬门禁）
- [ ] 推荐层 10/10（触发路由/编排/校验门禁/决策树/自进化/安全等）
- [ ] 可选层：需要项已启用且**真实运行验证过**（不是文档声称）
- [ ] orchestrator 状态机跑通 start→continue→settle
- [ ] 云端写入验证成功（凭据已配置）
- [ ] 定时任务真实存在并可触发
- [ ] 复盘闭环真实执行（Gotchas 在增长 / 经验库有数据）
- [ ] 端到端实测通过，结果可复现
