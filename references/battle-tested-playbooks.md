# 实战经验沉淀（Battle-Tested Playbooks）

> 本文档沉淀了3个实战验证过的方法论，来自数据分析类技能优化、多技能协同对齐、Agent编排器创建等真实项目。

---

## 方法论一：数据分析型技能7步优化法

| 步骤 | 动作 | 通过标准 |
|------|------|---------|
| 1. 现状审计 | 运行规范校验+深度审计，识别问题清单 | 问题按高/中/低优先级分类 |
| 2. 数据管道验证 | 端到端跑通数据采集→指标计算→决策树推荐 | 数据≥30期，指标≥30项，决策树7步全走 |
| 3. 方法论强制利用 | 检查决策树是否按方法论走，每步是否有明确结论 | 决策树7步全走，每步有评分和理由 |
| 4. 防偷懒机制 | 增加runtime_guard.py，track记录每步执行，gate门禁检查 | 5个门禁全部通过才能交付 |
| 5. 每步通过标准 | 每步定义明确的通过标准，用--quality参数记录质量指标 | 7步全部达标 |
| 6. 渐进式披露 | SKILL.md<300行，详细内容放references/，按需加载 | L1+L2+L3三层结构 |
| 7. 端到端实测 | 真实运行一期完整分析，验证所有环节 | 创建→优化→评审→结算全流程跑通 |

## 方法论二：多技能协同5步对齐法

| 步骤 | 动作 | 通过标准 |
|------|------|---------|
| 1. 统一路由格式 | 所有技能使用相同的路由行格式 | 路由格式一致，模式枚举一致 |
| 2. 统一工作流结构 | 所有技能使用相同的工作流结构 | 工作流步骤一致，自由度标注一致 |
| 3. 统一输出规范 | 所有技能使用相同的输出格式模板 | 输出格式一致，校验规则一致 |
| 4. 统一质量门禁 | 所有技能使用相同的runtime_guard.py机制 | 门禁检查项一致，通过标准一致 |
| 5. 交叉验证 | 用一个技能创建另一个技能，验证协同工作 | 创建→优化→评审全流程跑通 |

---

## 方法论三：Agent编排型6步创建法

| 步骤 | 动作 | 通过标准 |
|------|------|---------|
| 1. 角色定义 | 明确Agent的角色、目标、约束、语气、能力范围 | identity字段完整，角色定位清晰 |
| 2. 能力编排 | 规划Agent需要哪些技能、MCP服务器、内置工具 | capabilities字段完整，工具边界清晰 |
| 3. 工作流设计 | 设计Agent的工作流，定义每步的输入输出 | workflow字段完整，步骤清晰 |
| 4. 记忆配置 | 配置短期记忆、长期记忆、上下文窗口、压缩策略 | memory字段完整，符合Agent特点 |
| 5. 边界定义 | 定义Agent的always/ask_first/never边界 | boundaries字段完整，边界清晰 |
| 6. 评估标准 | 定义测试用例、成功标准、最低分数 | evaluation字段完整，可量化评估 |

## 跨案例通用方法论（5个核心原则）

1. **先审计后优化**：任何优化前先运行规范校验+深度审计，不要盲目做加法
2. **确定性推入代码**：能脚本做的就不要让LLM做，脚本做确定性计算，LLM做决策
3. **硬门禁比文字有效**：用runtime_guard.py的gate命令检查，不通过就不能交付
4. **渐进式披露**：SKILL.md<300行，详细内容放references/，按需加载
5. **端到端实测**：每阶段完成后必须真实运行，验证所有环节
