# 第一部分：自进化闭环手册

# 技能创建经验沉淀闭环详细手册

> 基于多个技能创建实战总结。经验沉淀是技能创建技能从"能用"到"越用越好"的关键，没有经验沉淀的技能创建工具每次都从零开始。
> 核心结论：**经验沉淀不是"复盘一下"，而是一个完整的闭环：技能创建→使用反馈→复盘→经验提取→案例库→下次创建参考，每个环节都有脚本支撑和硬校验。**
>
> **定位说明**：本手册针对"技能创建技能"设计，不是分析类技能。闭环的核心是"技能创建经验"的沉淀和复用，而不是"分析结果"的结算和复盘。

---

## 一、为什么经验沉淀至关重要

### 1.1 没有经验沉淀的技能创建工具会怎样

实战发现的问题：
```
问题1：连续多次创建的技能结构一模一样
  根因：没有复盘，LLM不知道之前的创建哪里好哪里差，继续重复同样的结构

问题2：模板选择准确率越来越低
  根因：没有统计各模板/设计哲学的创建成功率，不知道哪种模板在什么场景下更有效

问题3：设计哲学选择永远是同一种
  根因：没有各设计哲学的成功率统计，不知道哪种设计哲学在当前场景下更有效

问题4：创建经验只存在对话中，下次就忘了
  根因：没有案例库，LLM的创建经验无法沉淀和复用
```

### 1.2 经验沉淀的核心价值

| 价值 | 说明 |
|------|------|
| **错误纠正** | 每次复盘发现创建错误，下次避免重复 |
| **经验沉淀** | 有效的创建方法写入案例库，跨任务复用 |
| **数据驱动优化** | 创建成功率/质量统计驱动模板选择和设计哲学调整 |
| **质量校准** | 预期质量与实际质量对比，校准过度乐观/过度保守 |
| **技能进化** | 基于创建数据持续优化模板和方法论 |

## 二、经验沉淀闭环的6个环节

### 环节1：技能创建

**做什么**：按用户需求创建技能，记录创建方案。

**脚本支撑**：
- `create_skill.py start`：初始化创建任务，输出mandatory_steps和must_read
- `create_skill.py continue`：校验创建完整性，写入创建记录

**必须记录的字段**：
```
- 任务ID
- 技能名称
- 技能类型（数据分析/内容生成/工具包装/决策支持/自动化）
- 设计哲学（capability/process/mixed）
- 模板选择（init_skill_pro.py的模式）
- 创建时间
- 用户需求摘要
- 创建者（LLM/人工）
```

**硬校验**：
- 技能名称必须符合格式规范（小写+连字符，无特殊字符）
- 设计哲学必须在三种合法值中
- 缺任务ID/技能名称/设计哲学/用户需求，任何一项缺失就报错

### 环节2：使用反馈

**做什么**：技能创建完成后收集使用反馈，评估创建质量。

**脚本支撑**：
- `create_skill.py review`：自动运行规范校验+深度审计+输出校验
- `validate_skill.py`：规范校验
- `audit_skill.py`：深度审计
- `output_validator.py`：输出校验

**必须计算的字段**：
```
- 规范校验结果（高/中/低优先级问题数）
- 深度审计结果（必备层/推荐层/可选层达标数）
- 输出校验结果（必须修复/建议修复/可选修复问题数）
- 端到端测试结果（是否能正常触发和执行）
- 用户满意度（人工评估，可选）
- 质量等级（优秀/良好/合格/不合格）
```

**硬校验**：
- 规范校验必须运行，不能跳过
- 深度审计必须运行，必备层必须全部达标
- 输出校验必须运行，必须修复的问题必须修复
- 质量等级必须基于脚本计算，不能LLM凭感觉判断

### 环节3：复盘（6问清单）

**做什么**：按固定清单逐项复盘，不能凭感觉写"下次继续努力"。

**6问复盘清单**：

```
问1：需求vs实际
  - 用户需求的技能目标 vs 实际创建的技能目标
  - 用户需求的触发场景 vs 实际创建的触发场景
  - 用户需求的核心功能 vs 实际创建的核心功能
  - 满足了哪些？遗漏了哪些？

问2：设计哲学评估
  - 本次选择的设计哲学是否合适？
  - 如果选了其他设计哲学，结果会怎样？（反事实推理）
  - 各设计哲学的历史创建成功率对比
  - 当前场景下哪种设计哲学更有效？

问3：模板选择复盘
  - 本次选择了哪种模板（capability/process/mixed）？
  - 模板是否满足了技能需求？（模板选对了）
  - 有没有明显该用其他模板的情况？（模板选错了）
  - 各模板的历史创建成功率统计

问4：经验复盘
  - 本次用了哪些创建方法？
  - 哪些方法有效？哪些无效？
  - 有没有新的发现？
  - 案例库中有没有相关经验可以参考？

问5：质量校准
  - 本次预期的质量等级是多少？
  - 实际质量等级是否在预期范围内？
  - 是过度乐观（预期高但实际低）还是过度保守（预期低但实际高）？
  - 近10次创建的质量校准曲线

问6：下次改进
  - 下次创建需要调整什么？（模板/设计哲学/方法论/校验策略）
  - 有没有需要写入案例库的经验？
  - 有没有需要更新的模板推荐阈值？
```

**脚本支撑**：
- `create_skill.py review`输出复盘清单模板
- 案例库查询：检索相关经验

**硬要求**：
- 6问必须逐项回答，不能跳过
- 必须引用具体数据（任务ID/技能名称/质量等级/审计得分），不能凭感觉
- 反事实推理必须计算"如果选了其他设计哲学会怎样"

### 环节4：经验提取

**做什么**：从复盘中提取可复用的创建经验，写入案例库。

**案例库结构**：
```
- 案例ID（唯一标识）
- 标签（分类：设计哲学/技能类型/模板选择/创建流程/常见错误/最佳实践/工具使用）
- 内容（具体的经验描述，必须可执行）
- 质量等级（高/中/低，基于验证次数和成功率）
- 适用场景（什么情况下适用这个经验）
- 成功率（历史验证的成功率）
- 验证次数（被验证了多少次）
- 创建日期
- 最后验证日期
```

**经验提取的AI主动性问题**：
```
问题：创建完成后LLM不主动提取经验，案例库是空的
解决方案：
  1. SKILL.md强制要求："创建完成后必须提取至少1条经验写入案例库"
  2. create_skill.py review输出复盘清单时，最后一项必须是"经验提取"
  3. 下次创建时校验：如果上次没有提取经验，本次提示补充
  4. 案例库为空时，强制要求从历史创建记录中提取基础经验
```

**经验质量标准**：
- ✅ 好的经验："创建数据分析类技能时，使用混合型设计哲学+mixed模板，创建成功率比纯工具包装型高25%（历史统计20次创建验证）"
- ❌ 坏的经验："混合型设计哲学很好"（太模糊，不可执行，没有数据支撑）

### 环节5：案例库（持久化存储）

**做什么**：创建经验持久化到云端数据库，跨任务复用。

**案例库表结构**：
```
表名：技能创建案例库
字段：
  - 案例ID（文本，主键）
  - 标签（多选）
  - 内容（多行文本）
  - 质量等级（单选：高/中/低/核心）
  - 适用场景（多行文本）
  - 成功率（数字）
  - 验证次数（数字）
  - 来源（单选：复盘提取/人工添加/回测发现/外部导入）
  - 创建日期（日期）
  - 最后验证日期（日期）
  - 状态（单选：活跃/待验证/已降级/已删除）
```

**案例库的使用**：
```
1. 创建前：create_skill.py start从案例库读取最近20条高质量经验，输出给LLM参考
2. 创建中：LLM结合案例库经验做创建决策
3. 创建后：验证案例库中的经验是否仍然有效，更新成功率和验证次数
4. 定期：清理无效经验（成功率<30%且验证次数>10的经验降级或删除）
```

**案例库的自净化**：
```
- 新经验默认质量等级=低，验证次数=0
- 每次验证正确：验证次数+1，成功率更新
- 验证次数≥5且成功率≥60%：质量等级升级为中
- 验证次数≥10且成功率≥70%：质量等级升级为高
- 验证次数≥10且成功率<30%：质量等级降级，标记为"待验证"
- 验证次数≥20且成功率<20%：自动删除
```

### 环节6：下次创建参考（闭环）

**做什么**：下次创建时，自动加载案例库经验和历史复盘结果。

**脚本支撑**：
- `create_skill.py start`：从案例库读取最近20条经验，输出给LLM
- 案例库查询：按标签/质量等级/场景筛选经验

**输出格式**：
```json
{
  "experience_base": {
    "recent_experiences": [
      {"案例ID": "CASE-001", "标签": ["设计哲学"], "内容": "数据分析类技能用混合型+mixed模板成功率高25%", "质量等级": "高", "成功率": 75},
      {"案例ID": "CASE-002", "标签": ["常见错误"], "内容": "忘记运行validate_skill.py会导致高优先级问题流入交付", "质量等级": "中", "成功率": 80}
    ],
    "recent_reviews": [
      {"任务ID": "CREATE-20260921-001", "技能名称": "my-analyzer", "质量等级": "良好", "主要问题": "缺少Gotchas", "改进": "补充5个具体失败模式"}
    ]
  }
}
```

## 三、经验沉淀的指标监控

### 3.1 必须监控的指标

| 指标 | 计算方法 | 用途 |
|------|---------|------|
| 总创建成功率 | 成功创建数/总创建数 | 整体效果 |
| 各设计哲学成功率 | 各设计哲学成功数/各设计哲学执行数 | 设计哲学选择优化 |
| 各模板成功率 | 各模板成功数/各模板执行数 | 模板选择优化 |
| 平均创建时间 | 总创建时间/总创建数 | 效率评估 |
| 平均质量等级 | 质量等级得分总和/总创建数 | 质量评估 |
| 最大连续不合格 | 连续不合格的最大创建数 | 风险评估 |
| 最大连续优秀 | 连续优秀的最大创建数 | 趋势评估 |
| 质量校准误差 | 预期质量等级 - 实际质量等级 | 质量校准 |
| 案例库有效率 | 高质量经验数/总经验数 | 案例库质量 |
| 模板推荐Top1成功率 | 模板推荐正确率/总创建数 | 模板推荐优化 |

### 3.2 指标监控的脚本支撑

- `create_skill.py review`：每次创建后自动更新指标
- 案例库统计：统计各标签/质量等级的经验分布
- 云端存储：指标写入云端效果表

### 3.3 数据驱动优化

```
触发条件：
  - 某设计哲学连续5次创建成功率<20% → 降低该设计哲学基础分
  - 某模板连续10次创建成功率<50% → 标记为"待验证"
  - 模板推荐Top1成功率连续10次<30% → 重新校准模板推荐阈值
  - 质量校准误差>20% → 调整质量评估方法

优化流程：
  1. 指标监控发现异常
  2. 回测验证（用历史创建数据验证假设）
  3. 调整模板/设计哲学/方法论
  4. 试运行3次创建
  5. 效果验证（创建成功率/质量是否提升）
  6. 正式采纳或回滚
```

## 四、经验沉淀的演进历史

### v1.0：无经验沉淀（最差）
```
- 没有复盘，每次创建独立进行
- 没有案例库，创建经验只存在对话中
- 没有指标监控，不知道整体创建效果
- 结果：连续重复同样的创建错误，技能创建质量无法提升
```

### v2.0：有复盘但无闭环（改善有限）
```
- 创建后有复盘清单，但LLM经常跳过
- 经验提取靠LLM主动，经常不做
- 案例库为空或只有几条
- 结果：复盘了但经验没沉淀，下次还是犯同样的错
```

### v3.0：完整闭环+硬校验（有效）
```
- create_skill.py review强制输出6问复盘清单
- 复盘最后一项必须是经验提取
- 经验写入云端案例库
- create_skill.py start自动加载最近20条经验
- 指标监控自动更新
- 结果：错误纠正率提升60%，案例库持续增长，技能创建质量持续提升
```

## 五、检查清单：你的技能创建工具是否有完整的经验沉淀闭环

- [ ] 是否有创建记录表（持久化存储）？
- [ ] 是否有自动评估脚本（规范校验+深度审计+输出校验）？
- [ ] 是否有6问复盘清单（固定模板，不能跳过）？
- [ ] 是否有经验提取机制（创建后强制提取）？
- [ ] 是否有案例库表（持久化存储，结构化字段）？
- [ ] 经验是否有标签/质量等级/适用场景/成功率/验证次数？
- [ ] create_skill.py start是否自动加载案例库经验？
- [ ] 是否有指标监控（创建成功率/质量/各设计哲学表现）？
- [ ] 是否有数据驱动优化机制（指标异常→回测→调整→验证）？
- [ ] 案例库是否有自净化机制（无效经验自动降级/删除）？
- [ ] 质量是否有校准机制（预期vs实际对比）？

**0-4项**：经验沉淀严重不足，技能创建质量无法提升
**5-7项**：经验沉淀基本完整，但可能有断点
**8-12项**：经验沉淀完整，技能创建质量持续提升

## 自愈Agent模式

> 自进化是"事后改进"，自愈是"事中恢复"。两者互补：自进化让技能越用越好，自愈让技能出错时不崩溃。

### 三层自愈策略

```
第一层：自动重试（网络错误/限流）
  - 429限流/500错误/503服务不可用 → 指数退避重试3次
  - 重试间隔：1s→2s→4s，加随机抖动

第二层：降级运行（功能不可用）
  - 云端服务不可用 → 用本地缓存
  - 缓存也没有 → 提示用户+提供手动方案
  - 重要功能失败 → 至少输出部分结果+错误说明

第三层：事后修复（知识不足）
  - 遇到新错误 → 记录到经验库
  - 下次遇到同类错误 → 自动应用已学过的修复方案
```

### 技能中的自愈实现

| 层级 | 脚本实现 | LLM行为 |
|------|---------|---------|
| 自动重试 | `retry_with_backoff()` 装饰器 | 不需要LLM参与 |
| 降级运行 | `try-except` + fallback逻辑 | 检测到降级时告知用户 |
| 事后修复 | settle→复盘→经验提取 | LLM主动提取经验 |

### 检查清单

- [ ] 网络调用是否有重试机制？
- [ ] 重试是否有指数退避？
- [ ] 重试失败后是否有降级方案？
- [ ] 降级时是否告知用户？

# 第二部分：经验库指南

# 技能创建案例库建设完整指南

> 基于多个技能创建实战总结。案例库是技能创建技能从"能用"到"越用越好"的核心基础设施。
> 核心结论：**没有案例库的经验沉淀是断点——复盘了但经验没沉淀，下次创建还是犯同样的错。案例库必须结构化、可查询、自净化、持久化。**
>
> **定位说明**：本指南针对"技能创建技能"设计，不是分析类技能。案例库存储的是"技能创建经验"（创建方法/最佳实践/常见错误/模板选择），而不是"分析经验"（命中率/成功率/参数优化）。

---

## 一、为什么需要案例库

### 1.1 没有案例库的技能创建工具会怎样

实战发现的核心问题：
```
问题1：重复犯同样的创建错误
  根因：复盘了但经验没沉淀，下次创建还是犯同样的错

问题2：每次创建都从零开始
  根因：没有历史创建经验参考，每次都像第一次创建

问题3：有效的创建方法无法复用
  根因：某次发现的有效创建方法只存在对话中，下次就忘了

问题4：无法数据驱动优化创建流程
  根因：没有创建经验的成功率统计，不知道哪些方法有效哪些无效
```

### 1.2 案例库的核心价值

| 价值 | 说明 |
|------|------|
| **错误纠正** | 每次创建发现的错误写入案例库，下次避免重复 |
| **经验沉淀** | 有效的创建方法写入案例库，跨任务复用 |
| **数据驱动优化** | 创建经验的成功率统计驱动模板选择和流程调整 |
| **质量校准** | 经验的验证次数和成功率支撑质量评估 |
| **技能进化** | 基于案例库数据持续优化模板和方法论 |
| **冷启动加速** | 新用户可以从案例库快速获取基础创建经验，不需要从零摸索 |

## 三、经验提取的方法和流程

### 3.1 经验提取的时机

经验提取不是随时都做，而是在特定时机触发：

| 时机 | 触发条件 | 提取重点 |
|------|---------|---------|
| **创建完成后** | 每次创建/优化/评审/测试完成后 | 本次的成功经验和失败教训 |
| **错误发生时** | 出现明显错误或创建失败 | 错误原因和避免方法 |
| **成功复现时** | 某个方法连续3次创建有效 | 有效方法的适用条件和边界 |
| **回测发现时** | 历史创建记录回测发现规律 | 规律的统计显著性和适用范围 |
| **人工添加时** | 用户或开发者主动添加 | 领域知识和最佳实践 |

### 3.2 经验提取的流程

```
步骤1：复盘分析
  - 回顾本次创建的完整过程（需求→设计→模板→内容→校验→测试）
  - 识别成功点和失败点
  - 对比预期与实际，找出差异原因

步骤2：经验候选生成
  - 从成功点提取"什么有效"
  - 从失败点提取"什么无效"和"如何避免"
  - 从异常情况提取"边界条件"和"特殊处理"

步骤3：经验质量评估
  - 检查经验是否具体可执行（不是抽象规则）
  - 检查经验是否有数据支撑（不是凭感觉）
  - 检查经验是否有适用场景（不是万能药）

步骤4：经验格式化
  - 按照案例库结构填写所有字段
  - 选择合适的标签
  - 初始质量等级=低，验证次数=0

步骤5：经验入库
  - 写入案例库（持久化存储）
  - 记录创建日期和来源
  - 状态设为"待验证"
```

### 3.3 经验提取的AI主动性问题

```
问题：创建完成后LLM不主动提取经验，案例库是空的

解决方案（5层强制）：
  1. SKILL.md强制要求："创建完成后必须提取至少1条经验写入案例库"
  2. create_skill.py输出复盘清单时，最后一项必须是"经验提取"
  3. 下次创建时校验：如果上次没有提取经验，本次提示补充
  4. 案例库为空时，强制要求从历史创建记录中提取基础经验
  5. 输出校验：检查输出中是否包含新提取的经验
```

### 3.4 经验质量标准

#### ✅ 好的经验

```
1. 具体可执行：
   "创建数据分析类技能时，使用混合型设计哲学+init_skill_pro.py mixed模板"

2. 有数据支撑：
   "历史统计20次创建验证，创建成功率比纯工具包装型高25%"

3. 有适用场景：
   "适用于需要工具+判断的复杂数据分析任务"

4. 有边界条件：
   "对于简单的工具包装型技能，使用capability模板效率更高"
```

#### ❌ 坏的经验

```
1. 太模糊：
   "混合型设计哲学很好"（怎么好？什么场景下好？）

2. 没有数据支撑：
   "这个方法很有效"（有多有效？验证了多少次？）

3. 没有适用场景：
   "init_skill_pro.py很好用"（什么模式下好用？什么技能类型好用？）

4. 不可执行：
   "要注意技能质量"（怎么注意？具体做什么？）
```

## 四、案例库的使用机制

### 4.1 三阶段使用流程

#### 阶段1：创建前（加载经验）

```
做什么：从案例库读取相关经验，输出给LLM参考

脚本支撑：
- create_skill.py：从案例库读取最近20条高质量经验
- 按标签过滤：根据当前创建的技能类型/设计哲学，筛选相关经验
- 按质量等级排序：高质量经验优先展示

输出格式：
{
  "experience_base": {
    "recent_experiences": [
      {"案例ID": "CASE-001", "标签": ["设计哲学"], "内容": "...", "质量等级": "高", "成功率": 75},
      {"案例ID": "CASE-002", "标签": ["常见错误"], "内容": "...", "质量等级": "中", "成功率": 60}
    ],
    "filtered_by_tag": ["数据分析", "混合型"],
    "total_loaded": 2
  }
}
```

#### 阶段2：创建中（参考经验）

```
做什么：LLM结合案例库经验做创建决策

使用原则：
  1. 高质量经验（验证次数≥10且成功率≥70%）：直接采用
  2. 中质量经验（验证次数≥5且成功率≥60%）：参考使用，结合当前情况调整
  3. 低质量经验（验证次数<5或成功率<60%）：谨慎参考，需额外验证
  4. 待验证经验：仅作参考，不作为决策依据

必须做的事：
  - 输出中必须引用使用的案例ID
  - 说明为什么选择或不选择某条经验
  - 如果经验与当前情况冲突，说明如何处理
```

#### 阶段3：创建后（验证经验）

```
做什么：验证案例库中的经验是否仍然有效，更新成功率和验证次数

验证流程：
  1. 找出本次创建使用的所有经验（通过案例ID）
  2. 对比经验的预测与实际创建结果
  3. 如果经验预测正确：验证次数+1，成功率更新
  4. 如果经验预测错误：验证次数+1，成功率更新，检查是否需要降级
  5. 更新最后验证日期

自动升级/降级：
  - 验证次数≥5且成功率≥60%：质量等级升级为中
  - 验证次数≥10且成功率≥70%：质量等级升级为高
  - 验证次数≥10且成功率<30%：质量等级降级，标记为"待验证"
```

### 4.2 经验检索策略

| 检索方式 | 适用场景 | 实现方法 |
|---------|---------|---------|
| **按标签检索** | 知道经验分类 | 标签匹配，支持多标签组合 |
| **按质量等级检索** | 只看高质量经验 | 质量等级过滤，高>中>低 |
| **按场景检索** | 特定技能类型下的经验 | 适用场景字段匹配 |
| **按时间检索** | 最近的经验 | 创建日期/最后验证日期排序 |
| **按成功率检索** | 高成功率经验 | 成功率降序排列 |
| **全文检索** | 关键词搜索 | 内容字段全文匹配 |

**推荐策略**：组合使用标签+质量等级+场景，先过滤再排序，确保加载的经验既相关又可靠。

## 五、案例库的自净化机制

### 5.1 为什么需要自净化

```
问题：案例库如果只增不减，会出现：
  1. 无效经验堆积，干扰LLM判断
  2. 过时经验仍然被使用，导致创建失败
  3. 案例库越来越大，检索效率下降
  4. 低质量经验拉低整体案例库质量

解决方案：自净化机制——自动升级/降级/删除经验，保持案例库质量
```

### 5.2 质量等级自动升级

| 条件 | 操作 | 说明 |
|------|------|------|
| 验证次数≥5 且 成功率≥60% | 低→中 | 经过一定验证，效果尚可 |
| 验证次数≥10 且 成功率≥70% | 中→高 | 经过充分验证，效果良好 |
| 验证次数≥20 且 成功率≥80% | 高→核心 | 经过大量验证，效果优秀，标记为核心经验 |

### 5.3 质量等级自动降级

| 条件 | 操作 | 说明 |
|------|------|------|
| 验证次数≥10 且 成功率<30% | 高/中→待验证 | 效果不佳，需要重新验证 |
| 验证次数≥5 且 成功率<20% | 中→低 | 效果较差，降级处理 |
| 连续5次验证失败 | 任意→待验证 | 连续失败，立即标记 |

### 5.4 自动删除

| 条件 | 操作 | 说明 |
|------|------|------|
| 验证次数≥20 且 成功率<20% | 自动删除 | 经过大量验证仍然无效，删除 |
| 状态为"待验证"超过30天 | 自动删除 | 长期未验证，视为无效 |
| 重复经验（内容相似度>90%） | 合并保留高质量 | 去重，保留质量更高的 |

### 5.5 自净化执行时机

| 时机 | 执行内容 |
|------|---------|
| **每次创建后** | 更新本次使用经验的验证次数和成功率，检查升级/降级条件 |
| **每周定期** | 扫描全库，执行自动删除和去重 |
| **案例库超过1000条时** | 触发深度净化，清理低质量经验 |

## 六、案例库的持久化存储方案

### 6.1 三种存储方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **云端数据库** | 跨设备访问、多用户共享、支持复杂查询、自动备份 | 需要配置数据库、有网络依赖、可能有成本 | 生产级技能、多用户协作 |
| **本地JSON文件** | 简单易用、无依赖、可离线使用 | 不支持复杂查询、单设备、无自动备份 | 简单技能、个人使用、原型验证 |
| **混合方案** | 本地缓存+云端同步，兼顾性能和可靠性 | 实现复杂、需要处理同步冲突 | 中高级技能、需要离线支持 |

### 6.2 云端数据库方案（推荐生产级使用）

```
表结构：
  表名：技能创建案例库
  字段：
    - 案例ID（文本，主键）
    - 标签（多选）
    - 内容（多行文本）
    - 质量等级（单选：高/中/低/核心）
    - 适用场景（多行文本）
    - 成功率（数字）
    - 验证次数（数字）
    - 来源（单选）
    - 创建日期（日期）
    - 最后验证日期（日期）
    - 状态（单选：活跃/待验证/已降级/已删除）
    - 备注（多行文本）

索引：
  - 标签索引（加速按标签检索）
  - 质量等级索引（加速按质量等级过滤）
  - 状态索引（加速过滤已删除经验）
  - 创建日期索引（加速按时间排序）
```

### 6.3 本地JSON文件方案（推荐简单技能使用）

```
文件结构：
  experience-library.json
  {
    "version": "1.0",
    "last_updated": "2026-09-22",
    "experiences": [
      {经验对象1},
      {经验对象2},
      ...
    ]
  }

操作方法：
  - 读取：加载JSON文件到内存
  - 写入：修改后写回JSON文件
  - 查询：内存中过滤和排序
  - 备份：定期复制JSON文件到备份目录

注意事项：
  - 经验超过100条时考虑拆分文件
  - 每次写入前先备份
  - 使用原子写入（先写临时文件再重命名）
```

### 6.4 备份恢复机制

```
备份策略：
  1. 每次写入前自动备份（保留最近10个版本）
  2. 每天定时全量备份
  3. 每周异地备份（云端存储）

恢复流程：
  1. 发现数据损坏或丢失
  2. 从最近的备份恢复
  3. 验证恢复后的数据完整性
  4. 记录恢复事件和原因
```

## 七、案例库的冷启动

### 7.1 冷启动问题

```
问题：新的技能创建工具没有历史经验，案例库是空的
  - LLM没有经验参考，每次从零开始
  - 经验提取需要时间积累，前期效果差
  - 用户可能因为前期效果不好而放弃

解决方案：冷启动策略——快速获取基础经验，不需要从零摸索
```

### 7.2 冷启动策略

#### 策略1：人工注入基础经验

```
做什么：技能创建工具发布时，由开发者或领域专家注入10-20条基础经验

经验来源：
  - 技能创建最佳实践（渐进式披露/触发路由/must_read/编排脚本/硬门禁）
  - 常见错误和解决方案（忘记校验/跳过审计/文档不完整/脚本未测试）
  - 已知的有效方法和模板（init_skill_pro.py三种模式/validate_skill.py/audit_skill.py）
  - 历史项目的经验总结

注意事项：
  - 初始质量等级设为"中"（有人工验证但未经过实战验证）
  - 验证次数设为0（等待实战验证）
  - 来源标记为"人工添加"
```

#### 策略2：从历史创建记录回测提取经验

```
做什么：如果有历史创建记录，通过回测快速发现规律

流程：
  1. 收集历史创建记录（至少20次）
  2. 运行回测，测试各种模板和方法
  3. 发现统计显著的规律
  4. 提取为经验，写入案例库

注意事项：
  - 回测发现的经验需要标注"回测发现"
  - 初始质量等级设为"低"（回测有效不代表实战有效）
  - 需要实战验证后才能升级质量等级
```

#### 策略3：从相似技能迁移经验

```
做什么：如果有相似领域的技能创建工具，可以迁移其案例库

流程：
  1. 识别相似技能创建工具（相同领域或相似方法）
  2. 导出其案例库中的高质量经验
  3. 适配到新工具的标签体系和场景
  4. 写入新工具的案例库

注意事项：
  - 迁移的经验需要重新验证（不同工具的场景可能不同）
  - 初始质量等级降级一级（高→中，中→低）
  - 来源标记为"外部导入"
```

#### 策略4：快速迭代积累经验

```
做什么：在使用过程中快速积累经验，前10次创建重点提取

流程：
  1. 前10次创建每次必须提取至少2条经验
  2. 重点关注成功和失败的极端案例
  3. 快速验证经验的有效性
  4. 10次后案例库应该有20+条经验

注意事项：
  - 前期经验质量可能不高，需要持续验证
  - 定期清理无效经验
  - 关注经验的多样性，不要只提取某一类经验
```

## 九、案例库与经验沉淀闭环的关系

```
经验沉淀闭环6环节：
  技能创建 → 使用反馈 → 复盘 → 经验提取 → 案例库 → 下次创建参考
                                              ↓
                                      案例库是核心枢纽

案例库在闭环中的作用：
  1. 经验提取环节：经验写入案例库
  2. 案例库环节：经验持久化存储和管理
  3. 下次创建参考环节：经验从案例库加载，供下次创建使用
  4. 使用反馈环节：验证经验有效性，更新案例库

没有案例库的闭环：
  技能创建 → 使用反馈 → 复盘 → 经验提取（经验丢失）→ 下次创建参考（无经验可用）
  结果：断点，经验沉淀失效

有案例库的闭环：
  技能创建 → 使用反馈 → 复盘 → 经验提取 → 案例库（持久化）→ 下次创建参考（加载经验）
  结果：完整闭环，创建质量持续提升
