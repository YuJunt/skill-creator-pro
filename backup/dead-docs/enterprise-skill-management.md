# 企业级技能管理指南

> 基于Anthropic官方企业级Skills最佳实践。核心结论：**企业级技能管理不是堆技能，而是从窄开始、评估后合并、持续去重。**

---

## 一、核心原则：Start Specific, Consolidate Later

### 1.1 为什么从窄技能开始

```
❌ 错误做法：一开始就创建一个"全能文档处理技能"
  - description太宽 → 触发不精确
  - SKILL.md太长 → 上下文浪费
  - 一个技能做太多事 → LLM不知道走哪条路

✅ 正确做法：从窄技能开始
  - formatting-sales-reports（只管销售报告格式化）
  - analyzing-customer-data（只管客户数据分析）
  - reviewing-contracts（只管合同审查）
  - 等模式出现后，再评估是否合并
```

### 1.2 合并时机判断

**不要凭感觉合并，用eval数据驱动：**

```
合并前问3个问题：
  1. 两个技能的触发场景是否经常重叠？
  2. 合并后eval是否仍然通过？
  3. 合并后SKILL.md是否仍<500行？

三个都是"是"才合并。
```

## 二、技能去重

### 2.1 发现重复技能

| 检查项 | 方法 |
|--------|------|
| description重叠 | 列出所有技能的description，找关键词重叠>50%的 |
| 触发词冲突 | 列出所有触发词，找同一个词在多个技能中 |
| 功能重复 | 检查scripts/中是否有相似功能的脚本 |

### 2.2 去重决策树

```
发现两个技能功能相似
  ├─ 触发场景不同 → 保留两个，description写清楚区别
  ├─ 触发场景重叠
  │   ├─ eval A > eval B → 保留A，B标记deprecated
  │   ├─ eval B > eval A → 保留B，A标记deprecated
  │   └─ eval A ≈ eval B → 合并成一个，description更精确
  └─ 不确定 → 保留两个，收集使用数据3个月后再决策
```

## 三、技能组合原则

### 3.1 什么时候组合

| 场景 | 例子 |
|------|------|
| 多文档类型 | 数据分析（Excel）+ 演示文稿（PPT） |
| 多步骤流程 | 文档生成（Word）+ PDF导出 |
| 跨领域 | 定制业务逻辑 + 文档生成 |

### 3.2 什么时候不要组合

```
❌ 不要组合：
  - 没有使用过的技能（影响性能，占上下文）
  - 功能重叠的技能（触发混乱）
  - 不同用户角色的技能（应该按角色分发）
```

## 四、版本管理策略

### 4.1 Semver规范

```
MAJOR.MINOR.PATCH
  │     │    │
  │     │    └─ 向后兼容的bug修复
  │     └────── 新增功能，向后兼容
  └───────────── 破坏性变更（API/frontmatter/脚本接口）
```

### 4.2 破坏性变更检测

| 变更类型 | 是否破坏性 |
|---------|-----------|
| 修改SKILL.md内容 | ❌ 不破坏 |
| 新增references文件 | ❌ 不破坏 |
| 删除references文件 | ⚠️ 如果被SKILL.md引用则破坏 |
| 修改脚本参数 | ✅ 破坏 |
| 删除脚本 | ✅ 破坏 |
| 修改frontmatter字段 | ✅ 破坏 |

## 五、团队分发

### 5.1 分发方式

| 方式 | 适用场景 |
|------|---------|
| GitHub仓库 | 开源/社区共享 |
| 内部Git仓库 | 团队/公司内部 |
| Claude API workspace-wide | 企业级集中管理 |
| 手动上传 | 个人使用 |

### 5.2 分发检查清单

- [ ] SKILL.md符合规范（validate_skill.py通过）
- [ ] 安全扫描通过（security_scan.py）
- [ ] 无硬编码凭据
- [ ] 脚本有错误处理
- [ ] 有README或使用说明
- [ ] 版本号正确
- [ ] changelog已更新
- [ ] 至少3个eval用例通过

---

## 六、检查清单

- [ ] 是否从窄技能开始而非全能技能？
- [ ] 是否有技能去重机制？
- [ ] 合并技能前是否跑了eval对比？
- [ ] 是否有版本号管理？
- [ ] 破坏性变更是否bump MAJOR版本？
- [ ] 分发前是否跑了完整校验？
- [ ] 是否有使用统计驱动优化？

**0-2项**：技能管理混乱，技能越积越多但质量下降
**3-5项**：基本管理，有规范但执行不够
**6-7项**：企业级管理，技能库健康可持续
