# 盲比较A/B测试指南（Blind Comparator）

> 基于harnez.ai和piax.org的skill-creator v2实践。核心结论：**版本对比时，不知道哪个是A哪个是B，才能消除偏见——否则你总是认为自己的新版本更好。**

---

## 一、为什么需要盲比较

### 1.1 偏见问题

```
❌ 非盲比较（有偏见）：
  你知道A是旧版，B是你刚改的新版
  → 你倾向于认为B更好（因为你刚改的）
  → 实际上B可能更差

✅ 盲比较（无偏见）：
  你只看到输出A和输出B，不知道哪个是新版
  → 你纯粹根据质量判断
  → 结果更可信
```

### 1.2 三个角色

| 角色 | 职责 | 说明 |
|------|------|------|
| **Grader（评分器）** | 对照断言逐项评分 | PASS/FAIL，引用证据 |
| **Comparator（比较器）** | 盲A/B比较 | 不知道哪个是新版，只看质量 |
| **Analyzer（分析器）** | 汇总基准数据 | 哪些断言有区分度，方差在哪 |

## 二、盲比较执行流程

### 步骤1：准备

```
准备：
  - 版本A（旧版技能）
  - 版本B（新版技能）
  - 3-5个测试任务

对每个测试任务：
  1. 用版本A跑一次 → 保存输出为 outputA
  2. 用版本B跑一次 → 保存输出为 outputB
  3. 随机打乱A/B标签（可以是A/B或B/A）
```

### 步骤2：盲比较

```
给比较器的输入：
  - 任务描述
  - 输出X（不知道是A还是B）
  - 输出Y（不知道是A还是B）
  - 评分标准（rubric）

比较器做：
  1. 分别读X和Y
  2. 对照rubric打分（1-10分）
  3. 说明理由
  4. 选更好的那个

关键：比较器不知道X和Y哪个是新版
```

### 步骤3：揭晓结果

```
揭晓：
  - 如果比较器选的是新版 → 新版确实更好
  - 如果比较器选的是旧版 → 新版可能更差，需要回退
  - 如果打平 → 变化不明显，考虑是否值得
```

---

## 三、评分标准（Rubric）

### 通用评分维度

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 任务完成度 | 30% | 是否完成了任务要求 |
| 输出正确性 | 25% | 结果是否正确 |
| 输出完整性 | 20% | 是否包含所有必要部分 |
| 可读性 | 15% | 是否清晰易懂 |
| 简洁性 | 10% | 是否没有废话 |

### 评分方法

```
每个维度1-10分：
  9-10：优秀，无明显问题
  7-8：良好，少量小问题
  5-6：及格，有明显问题但可用
  3-4：较差，有严重问题
  1-2：极差，不可用

总分 = Σ(维度分 × 权重)
```

## 四、什么时候用盲比较

| 场景 | 适合盲比较？ |
|------|------------|
| 改了SKILL.md结构 | ✅ 对比前后输出质量 |
| 新增/删除gotcha | ✅ 对比是否改善了行为 |
| 换了脚本实现 | ✅ 对比输出是否一致 |
| 改了references内容 | ✅ 对比分析深度 |
| 纯格式调整 | ❌ 不需要 |
| 修了明显bug | ❌ 直接确认修复即可 |

## 六、检查清单

- [ ] 是否有版本A/B的输出？
- [ ] 是否随机打乱了标签？
- [ ] 比较器是否不知道哪个是新版？
- [ ] 是否有评分rubric？
- [ ] 是否每个维度都打了分？
- [ ] 是否说明了理由？
- [ ] 结果是否可信？（如果新版总是赢，可能有偏见）

**0-2项**：盲比较不规范
**3-5项**：基本规范
**6-7项**：专业盲比较
